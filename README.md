# Cassandra-Collective/.github

The organisation's home repository on GitHub.

| Path | What it holds |
|---|---|
| [`profile/README.md`](profile/README.md) | The page GitHub shows at [github.com/Cassandra-Collective](https://github.com/Cassandra-Collective) once this repository is public |
| [`brand/`](brand/README.md) | The CASSANDRA identity: the Forecast mark, lockups, palette, typography, every file format, and the scripts that build and check them |
| [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md) | The organisation's code of conduct: the Contributor Covenant 2.1 |
| [`CONTRIBUTING.md`](CONTRIBUTING.md) | The organisation's general contributing guide, with the rules for this repository at the end |
| [`SECURITY.md`](SECURITY.md) | How to report a security problem privately, and what to expect |
| [`SUPPORT.md`](SUPPORT.md) | Where to ask questions, and what to include |
| [`.github/ISSUE_TEMPLATE/`](.github/ISSUE_TEMPLATE/) | Default issue forms (bug report, feature or improvement, question) and the template chooser's `config.yml` |
| [`.github/pull_request_template.md`](.github/pull_request_template.md) | The default pull request template |
| [`docs/implementations/`](docs/implementations/) | One document per change: what was done, why, and how it was verified |

GitHub only shows `profile/README.md` publicly when this repository is public. A members-only profile goes in a separate repository named `.github-private`.

The code of conduct, contributing guide, security policy, support guide and templates are organisation defaults: GitHub uses each one for every repository in the organisation that has no file of that type of its own. A repository's own file always takes precedence. Issue forms are all or nothing: a repository with its own issue templates or `config.yml` in `.github/ISSUE_TEMPLATE` uses none of the defaults.
