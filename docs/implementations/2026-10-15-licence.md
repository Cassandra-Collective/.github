## Problem / Motivation

This repository had no licence file. By default that means nobody outside it may reuse anything in it, yet:
- the brand guide (`brand/README.md`) tells readers how to use the logo files, in slides, documents, LaTeX and websites, so readers could fairly assume they may;
- the scripts in `brand/tools/` invite contributions, and a contribution to code without a licence leaves both sides unsure of its terms;
- GitHub's community profile scored the repository at 75%, the only gap being the missing licence.

Issue #13 asked the owner three questions. On 2026-10-15 the owner chose "Apache-2.0 + CC BY-ND for marks". The answers:

| #13 asks | Answer |
|---|---|
| 1. Publish usage terms for the logo files? | Yes. |
| 2. In what form? | A licence for the artwork, CC BY-ND 4.0, alongside the guide's existing "Don't" rules, which say how to use the files well. |
| 3. A separate licence for `brand/tools/`? | Yes: the scripts, like the rest of the repository's text and code, are under the Apache License 2.0. |

## Implementation Approach

**Two licences, split by folder.**

| Part | Licence | Where |
|---|---|---|
| Scripts, documentation, the organisation profile, community files, issue and pull request templates | Apache License 2.0 | `LICENSE` |
| Brand assets: marks, lockups, social cards, icons, avatar, favicons, guide figures and their VectorCraft sources | CC BY-ND 4.0 | `brand/LICENSE-BRAND.md`, covering `brand/svg/`, `png/`, `pdf/`, `eps/`, `web/`, `guide/` and `source/` |

**Exceptions** keep their own licences, listed in `NOTICE`:
- `CODE_OF_CONDUCT.md` is the Contributor Covenant 2.1, under CC BY 4.0, as its attribution already says.
- The Ionic column and pixel wordmark in the Ephesus card, and their data in `brand/tools/ephesus_artwork.json`, come from Ephesus under its MIT License (Copyright (c) 2026 Mert Efe Şensoy, as Ephesus's `LICENSE` says).
- The letterforms are outlines of Source Serif 4, Inter and IBM Plex Mono, under the SIL Open Font License 1.1. No font software is distributed here.

**The legal texts are verbatim.** `LICENSE` is the Apache text exactly as apache.org publishes it (line endings normalised to LF), because GitHub detects a licence by matching the file against the known text. The CC BY-ND 4.0 legal code in `brand/LICENSE-BRAND.md` is copied exactly from `creativecommons.org/licenses/by-nd/4.0/legalcode.txt`, inside a fenced `text` block so Markdown leaves its layout alone. Only the header above it is ours.

**Inbound and outbound terms differ, on purpose.** Contributors contribute under Apache-2.0, including changes to the brand scripts and any brand files rebuilt from them. The repository then publishes the brand files under CC BY-ND 4.0. Apache-2.0 allows a recipient to distribute a work built from a contribution under other terms (its section 4), so this is consistent. The reverse, taking contributions under CC BY-ND, would forbid the maintainers themselves from changing or rebuilding a contributed file.

**Where licences apply in the organisation.** A `LICENSE` file in `.github` is not an organisation default: GitHub carries only community health files (code of conduct, contributing guide, security policy, support guide, templates) over to other repositories. CASSANDRA, CASSANDRA-Chorus, Dervish and Ephesus keep their own licences, unchanged by this change.

## Design Decisions

| Decision | Alternatives | Why | Who |
|---|---|---|---|
| Apache-2.0 for the code and text, CC BY-ND 4.0 for the brand assets | One licence for everything (Apache-2.0, or MIT); all rights reserved with a brand-use policy; CC BY 4.0 for the assets | Code stays freely usable and contributable; the marks may be shared, as a talk or an article needs, but not altered | Owner, 2026-10-15 |
| Copyright holder: Mert Efe Şensoy | "The Cassandra Collective" | The Collective is a GitHub organisation, not a legal entity that can hold copyright; Ephesus's `LICENSE` names the same holder | Engineering default, for the owner's review |
| Inbound Apache-2.0, outbound CC BY-ND for brand files | Inbound CC BY-ND for brand files | An ND grant to the maintainers would stop them changing a contributed file; the guide already says brand changes are made in the scripts, not in exported files | Engineering, for the owner's review |
| The full CC legal code in `brand/LICENSE-BRAND.md` | A link to creativecommons.org only | The terms travel with the files; the copy is the published text, unmodified | Engineering |
| The scope header names folders, not files | A list of every licensed file | The build adds files; a folder list stays true as it does | Engineering |

**A known tension, recorded for the owner.** `build_brand.py` is Apache-2.0, and it encodes the marks' geometry, so a reader could argue that running or changing the script yields marks they may use and alter. `NOTICE` and `brand/LICENSE-BRAND.md` state the licensor's position: the Apache licence covers the scripts as software; the designs they draw and the files they produce are brand assets under CC BY-ND 4.0; and neither licence grants trademark rights (Apache-2.0 section 6, CC BY-ND 4.0 section 2(b)(2)). Stating the position does not settle it in law. For marks, the stronger protection is usually trademark, not copyright, and simple geometric marks may not reach the threshold for copyright at all. No trademark is registered. Issue #13's other pointer stays open as well: the Apache Software Foundation lists "Cassandra" as a trademark of its database software (`brand/README.md`, "Notes").

## Verification

1. **Apache text.** `LICENSE` was fetched from `https://www.apache.org/licenses/LICENSE-2.0.txt` and only its line endings were changed. Its SHA-256 begins `cfc7749b96f63bd3`.
2. **Brand check.** `python brand/tools/check_brand.py` printed `ALL CHECKS PASSED`. Its "unexpected file" scan covers only the output folders, so `brand/LICENSE-BRAND.md` does not trip it.
3. **Dashes.** No em or en dash appears in our own prose: every changed or new file, excluding `LICENSE` and the fenced legal code in `brand/LICENSE-BRAND.md`, which are published texts. (The legal code itself contains none.)
4. **GitHub's detection, before merge.** `gh api "repos/Cassandra-Collective/.github/license?ref=docs/licence"` returned 404: the endpoint reads the default branch only, so it cannot check a branch. Instead, `LICENSE` was compared with GitHub's own template, `gh api licenses/apache-2.0 --jq .body`. After collapsing whitespace the two are identical, 1,581 words each, so GitHub's detector, which matches against that template, should report Apache-2.0.
5. **After merge:** the repository's About panel should show "Apache-2.0 license", and `gh api repos/Cassandra-Collective/.github/community/profile --jq .health_percentage` should rise from 75 towards 87, the ceiling while issue forms replace legacy templates.

**Not tested:** how GitHub labels a repository with two licences (it reports the one in `LICENSE`); whether the CC BY-ND terms would hold for these particular marks in any court.
